# Nacos 配置导入导出

状态：产品行为与工程方案已于 2026-11-09 获得整体确认并实现，验证结果见[实现与验收记录](nacos-import-export-implementation.md)。

依据：[Nacos 导入导出调研](nacos-import-export-research.md)、工作区样本 `nacos_config_export_20261109112754.zip` 和用户提供的 Nacos 多选导出界面。

## 已明确的边界

- 配置管理支持选中配置后导出，在现有多选操作区域提供导出入口。
- 支持导入 Nacos 导出的配置包；ConfHub 导出的包也应能够被 Nacos 导入，实现文件格式互通。
- 本轮以样本使用的新版 ZIP 为兼容基线：正文路径 `group/dataId`，根目录 `.metadata.yml` 保存 `metadata` 列表。
- 一期只支持 `.metadata.yml` 新格式，不支持 `.meta.yml` 旧格式或缺少元数据的普通 ZIP。新旧表示文件格式，不能等同于 Nacos 2.x/3.x；Nacos 2.5.1 的新版导出同样受支持。
- `type` 映射到格式，`desc` 映射到本次主版本的 description；`appName` 导入忽略，导出设为空字符串。未知格式或正文不符合声明格式时整包拒绝，不自动转换为纯文本。
- 配置名原样保留，不能按格式补充或变更文件扩展名；正文保持原始文本，不自动格式化。
- 配置导出包携带当前全量配置及可交换元数据，不作为源历史、灰度规则或权限的完整备份。
- ZIP 不携带源命名空间，导入目标命名空间必须由系统上下文或用户选择明确给出。
- 简单交互和默认行为参考 Nacos；与 ConfHub 现有发布、权限及并发约束发生冲突的地方另行明确。
- 导入使用整包事务：成功时统一提交，任意校验、权限、并发或写入错误都不保留本批配置修改。与 Nacos 的逐项提交不同，见 [整包导入决策](adr/0009-atomic-configuration-import.md)。
- 覆盖已有配置沿用普通全量保存：生成下一个主版本并立即全量发布，已有 beta 和规则保留；正文和格式相同时不产生重复主版本。沿用现有规则，仅 description 不同时也不更新已发布主版本。
- 导入弹窗选择 ZIP、目标 namespace 和冲突策略，保留包内 Group；解析后展示数量、冲突和错误，由用户统一确认，不逐份要求 diff 确认。
- 同时提供“导出选中”和“导出全部”；全部指当前 namespace/group 下符合搜索条件的所有分页。勾选沿用当前页选择，翻页清空，不跨页累计。
- 目标 namespace 必须存在。系统管理员可在导入事务中创建缺失 Group；普通用户只能导入已经存在且有写权限的 Group，否则整包拒绝。
- 导出属于 config.read，读取用户也可勾选；删除、移动仍要求 config.write。导入逐目标 group 校验 config.write；只读实例允许导出、禁止导入。
- 保留中止/跳过/覆盖，默认中止。中止策略发现任何重名冲突即整包不提交；跳过只排除预览中已存在的配置，其余待写配置统一提交；覆盖沿用普通全量保存。
- 提交时再次校验预览中的待写配置身份和修订；出现修改、删除重建或新建抢占，整包冲突并要求重新预览确认。不得在覆盖策略下静默覆盖预览后发生的新变更。

## 已确认实施方案

### 文件解析与导出

- 导出使用 `group/name` 路径及根 `.metadata.yml`，metadata 列表条目包含 dataId、group、type、desc、appName。只导出一个 namespace 的当前全量配置，支持包内多个 group 的格式，但本期 UI 的导出范围遵循当前单 group 筛选。
- 导出读取点击请求处理时的一致性快照，不使用勾选时的旧版本；选中项已不存在时明确报错，不静默漏项。正文不格式化，不补扩展名，不变更换行、缩进或空白。
- 新版 metadata 必须非空且与全部正文路径一一对应。拒绝重复 metadata key、重复 ZIP 文件名、缺失或额外正文、非法 UTF-8、绝对路径、路径穿越及超出两段的正文路径；允许忽略普通目录条目。
- 采用项目已有名称、正文和 description 校验。支持格式为 text/json/yaml/toml/xml/properties/ini；`desc` 缺省或 null 归为空字符串；appName 不存储，不承诺应用归属字段往返保真。
- 工程上限为 1,000 份配置、单份正文 1 MiB、正文与 metadata 解压总量 64 MiB、上传 ZIP 8 MiB；读取时强制检查解压上限，导出超过条数/字节限制时整次报错，不截断输出。上传沿用全局请求体 8 MiB 限制，因 multipart 开销实际 ZIP 可用大小略小。上限作为本轮默认实现常量，不新增启动配置。

### 导入预览与提交

- 预览解析整个包，完成格式、组织、权限和冲突检查，返回每项的新建/覆盖/跳过/不变/错误结果及数量。存在阻塞错误时不能确认；策略或目标 namespace 改变后重新预览。
- 确认时提交同一个 ZIP、目标 namespace、策略及预览得到的待写项身份/修订基线。服务端重新解析、核对文件指纹及目标策略，再检查当前请求权限；不能信任前端宣称的正文校验结果。
- 不在实例内持久保存待确认导入任务，使预览和确认可由不同实例处理。包正文不放入数据库草稿表，不引入定时清理任务。
- 一个事务内检查待写基线、按需创建允许的 Group、保存新主版本和变更事件。任意错误回滚所有配置与分组变更；成功提交后再唤醒通知。全部跳过或不变时返回成功统计，不生成多余版本与配置变更事件。
- 与现有 Save 共用业务规则，提取可复用的事务内保存逻辑，保留普通单配置保存行为；不额外建立一套导入版本规则。默认不新增表结构迁移。
- 导入结果区分新建、覆盖、跳过、不变和整包失败；失败时明确本批未提交，提供定位到 group/name 的错误信息，不展示配置正文到日志。

### 前端与权限

- 配置列表的可选能力归入读取权限；有选择时在现有批量区提供导出入口。删除和移动仍仅对有写权限的用户出现。
- “导出全部”在没有勾选时也可使用，范围提示明确为当前 namespace/group 与搜索条件的全部分页。
- 导入位于配置管理操作区，默认当前 namespace，允许选择已有且可写的目标 namespace；包内 group 保持原样。
- 导入弹窗包含文件、namespace、策略、预览和确认，确认按钮明确表示导入并发布；不添加逐份 diff 流程。成功后刷新配置与 Group 列表。
- 服务端分别授权导入和导出，错误不得泄漏无权限配置正文。只读实例提供导出，禁止预览后提交导入。
- 新增导入/导出审计动作，记录用户、来源 IP、时间、目标 namespace/group、策略、数量及结果，不记录 ZIP 内容或配置正文；只读实例沿用不写审计的现有规则。

### 验收安排

- 单元测试：新格式解析/生成、全部支持的格式、描述和 UTF-8/换行保真、重复或不配对条目、旧格式拒绝、路径与解压上限。
- 真实 PostgreSQL 集成：中止/跳过/覆盖、全量版本和 beta 保留、相同正文不重复发布、缺失 Group 权限及创建回滚、写入途中失败整包回滚、预览后更新/删除重建/新建抢占、权限和审计。
- 公共 API 与正式 SDK：导入完成后普通及灰度客户端行为、跨实例读取/通知、只读导出和写入拒绝、筛选与选中导出范围。
- 前端单测/浏览器：读取用户选择与导出、写入按钮权限、选中/全部、文件上传预览与确认、冲突结果、并发后重新确认、明暗与窄屏交互。
- 双向互通：只读使用工作区真实样本验证 12 份配置；用虚构配置生成可提交的测试样本，防止提交真实正文。临时部署实际 Nacos，验证 Nacos 新版导出 → ConfHub 导入，以及 ConfHub 导出 → Nacos 导入，再逐项比较 group/dataId/type/desc/正文；测试后删除临时环境。不把仅自家解析器往返当作 Nacos 兼容验证。

## 已核对的现有行为

- [配置列表](../frontend/src/pages/config-list.tsx) 固定一个 namespace/group，每页 25 条，多选和批量操作仅在拥有 `config.write` 时出现；切换分页、搜索、namespace 或 group 会清空选择。增加读取性质的导出，需要调整这一权限条件；跨页或跨 group 多选不属于现有能力。
- [组织权限](../internal/server/users.go) 将新建 namespace/group 归入 `organization.manage`；配置写权限不自动包含分组创建权限。
- [配置保存](../internal/storage/configs.go) 要求 group 已存在，不自动创建；更新校验配置身份与修订以防并发覆盖。
- 当前全量保存以正文和格式判定重复；即使 description 不同也直接不保存。需要在导入描述映射中明确此边界，不能承诺描述总能覆盖。
- 每次普通保存独立提交，现有批量删除/移动则使用整批事务；本次整包导入需要复用保存规则并共享外层事务，不能直接循环调用独立提交的 Save。
- [只读模式](../internal/server/readonly.go) 按 HTTP 方法和少量明确例外拦截写请求；导出应按读取性质分类，不能因为采用 POST 就被误判为配置写入。
- [服务入口](../internal/server/server.go) 当前请求体上限为 8 MiB；ZIP 解压后的总字节数与条目数需要另行限制。前端 [API 工具](../frontend/src/lib/api.ts) 当前默认 JSON，需为 ZIP 下载和 multipart 上传提供适当处理。

导出权限、缺失分组、并发冲突和格式兼容范围均已结合这些事实由用户确认。
