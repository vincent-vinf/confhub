# 操作审计

系统管理员在控制台“操作审计”查看所有管理操作。普通用户不能进入页面或调用查询接口；审计没有单独的普通用户授权开关。支持按用户名、来源 IP、操作、结果、开始和结束时间组合筛选，以及分页、手动刷新和详情查看。

## 记录内容和范围

每条记录包含请求 ID、开始时间、操作用户 ID/用户名、连接 IP、HTTP 方法、操作、对象、结果、HTTP 状态和耗时。用户与对象名称采用快照，不关联删除后的账号或配置，因此删除不会删除历史审计。失败登录仅保存尝试的用户名，不能据此认定该用户身份；没有有效认证的请求显示“未认证”。

| 范围 | 操作 |
| --- | --- |
| 账号认证 | 登录成功/失败、退出、修改本人密码 |
| 用户管理 | 创建、修改权限和状态、重置密码、删除 |
| 组织管理 | 创建/删除 namespace 和 group |
| 配置变更 | 全量保存发布、beta 覆盖、规则修改、回退、灰度转全量、删除、批量删除和移动 |
| 配置读取 | 打开配置正文、读取历史版本正文、匹配模拟 |

这些接口的认证失败、权限拒绝、来源拒绝、校验失败和并发冲突也会记录。正文/历史的打开可能因重新请求产生多条读取记录；一次 HTTP 请求对应一条审计，未变化的保存也记录成功，详情中 changed=false。

组织/配置/用户/历史元数据列表、当前身份、在线客户端/标签、审计查询、健康检查和静态资源不记录，避免后台刷新产生大量审计。匿名 SDK HTTP GET/WebSocket 不记录；SDK 流量没有可验证的管理用户身份。

详情仅包含业务白名单字段，例如配置 ID、主版本、来源版本、规则名称/顺序/启用状态/条件数量、用户授权范围和批量操作的配置键及目标组织。不保存密码、密码摘要、JWT/Cookie、配置正文、配置描述、标签值或原始请求/响应。显示的耗时是开始记录至操作响应生成的时间，不包含最后的审计完成写入。

IP 使用实际 HTTP 连接对端并统一 IPv4 映射格式，不信任 X-Forwarded-For/X-Real-IP 等请求头。直连时记录客户端地址；经过反向代理时记录代理地址。本次没有新增信任代理参数。

## 持久化和故障语义

各实例共享数据库 audit_logs，由 GORM 常规读写，表结构通过 golang-migrate 管理。开始记录与已认证操作者身份在业务处理前同步持久化；无法持久化时返回 503 并阻止处理。业务结束后将 pending 更新为 success/failure；请求取消后仍使用独立的 3 秒超时完成写入。

| 结果 | 含义 |
| --- | --- |
| success / 成功 | HTTP 响应为 2xx，审计完成写入 |
| failure / 失败 | HTTP 响应非 2xx，审计完成写入 |
| pending / 结果未确认 | 请求仍在处理、进程中断，或完成审计写入失败；业务可能已经提交 |

开始审计、业务事务与完成审计不是同一个事务。pending 不代表失败，也不会自动重放或推断业务结果；可按请求 ID、对象及当前配置核对。未完成的记录可能仅有请求路径对象，缺少最终详情；登录等尚未验证身份的请求可能没有操作用户。数据库不可用导致首次记录失败时，仅输出不含正文的服务错误日志，数据库中无法留下该次审计。

没有面向管理端的审计修改/删除接口；数据库管理员仍可操作数据。当前保留全部审计，不随配置历史清理，不设置自动过期。这是应用操作记录，不提供密码学防篡改或客户端应用确认。

## 查询 API

`GET /api/admin/audits`，需要已登录的系统管理员（audit.read）。

| 参数 | 语义 |
| --- | --- |
| username | 精确用户名，同时匹配操作用户与尝试登录用户名 |
| ip | 精确 IPv4/IPv6，IPv4-mapped IPv6 归一化，无 zone |
| action | 精确操作编码，例如 config.publish、user.update、auth.login |
| result | success、failure、pending |
| from / to | RFC3339 时间，包含开始，不包含结束；数据库精度微秒 |
| before | 上一页 next_before，以字符串传递 |
| limit | 默认 25，范围 1–100 |

按递增审计 ID 倒序分页，ID 和 next_before 返回十进制字符串，避免 JavaScript 大整数精度损失。新记录不会移动已有游标之后的记录；正在执行的请求完成后，其结果筛选可见性会变化。时间以 UTC 返回，页面按浏览器本地时间展示和提交筛选。

```json
{
  "audits": [{
    "id": "42",
    "request_id": "41ec93ca-ad52-4b09-8e2a-27ec0fb59ebc",
    "created_at": "2026-10-12T12:00:00Z",
    "user_id": "00000000-0000-4000-8000-000000000001",
    "username": "admin",
    "ip": "192.168.2.5",
    "action": "config.publish",
    "subject": "public / DEFAULT_GROUP / app.yaml",
    "method": "PUT",
    "result": "success",
    "status": 200,
    "duration_ms": 8,
    "details": {"changed": true, "global_version": 4}
  }],
  "next_before": "42"
}
```

操作编码全集及中文名称见 frontend/src/pages/audits.tsx；服务端入口分类见 internal/server/audit.go。被审计请求响应提供 X-Request-ID，可与记录关联。

## 升级与验证

schema 6 新增 audit_logs 及查询索引，PostgreSQL/MySQL 均提供迁移。从 schema 4/5 停止旧实例，使用新二进制执行 `confhub migrate`，再重启全部实例；保留原配置、用户和授权，不回填旧操作。空数据库首次启动自动初始化到 schema 6，schema 1/2/3 仍按原策略重建。

PostgreSQL 集成测试覆盖记录状态、筛选边界、分页与并发、账号删除后保留身份、全部审计操作和敏感信息排除、伪造转发 IP、认证/权限/来源/并发失败、后台查询排除、审计故障阻止操作及完成失败保留 pending、schema 4/5 升级。浏览器覆盖组合筛选、时间校验、分页、详情、普通用户限制及明暗主题/手机布局。测试入口见 [testing.md](testing.md)。
