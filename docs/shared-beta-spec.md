# 配置级唯一 beta

用户最新要求取代按规则独立 beta：一个配置最多一份 beta，所有有序规则命中后都使用它；beta 与主版本号无关，名称固定 beta。历史列表最前面展示 beta，支持直接编辑，保存覆盖并立即生效，不产生新版本。首次创建规则时选择从哪个保留主版本复制。

已确认边界：
- 不兼容旧数据，schema 1/2/3 均拒绝启动和 migrate；新的空数据库初始化 schema 4。不删除用户现有数据。
- 删除最后一条规则同时删除 beta；下一次新增规则重新选择来源。全部停用保留 beta，未命中回到全量。
- 条件仍 AND，规则按顺序第一条命中；rule_id 只说明命中条件，不决定独立正文。
- beta 无编号、无主历史依赖。初次 source_version 是一次性复制输入，不保存为 beta 名称或目标引用；来源被清理不影响 beta。
- state.beta 为唯一可选正文；rules 只有元数据。编辑通过 target=beta，不按 rule_id。主版本 rollback 保持 beta。beta 转全量读取唯一 beta，生成下一个主版本，保留 beta/规则，内容和格式相同沿用无变化行为。
- HTTP/WebSocket 有效状态 beta=true、version=0 表示无编号的 beta；全量 beta=false、version 为递增主版本。SDK/缓存/在线客户端展示同步更新，beta 同名原位编辑仍推送正文变化。
- 保留格式校验、乐观锁、保存前与当前 beta 的 diff 和勾选确认。编辑后确认立即生效，不保留 beta 修改历史。历史顶部直接编辑 beta 跳转同一编辑目标，只有一个 beta 选项，没有灰度回退按钮。
- 历史顶部 beta 是当前可修改内容的入口，主历史 API 与保留配额仅含主版本，不把 beta 混入不可变版本列表。每页主历史展示前始终显示唯一 beta 行。
- 无 beta 时新增第一条规则必选复制主版本；后续规则没有复制入口。首次创建冲突后保留选择但重新验证来源仍存在及最新配置身份，不自动切换来源。
- 继续使用已批准测试边界、PostgreSQL 17 指定镜像；先改后端、再改前端，SDK 随协议一起改。
