实现日期：2026-10-09。需求依据为 [requirements.md](requirements.md)、[architecture.md](architecture.md) 和 [backend-api.md](backend-api.md)。视觉规则见 [设计系统](../design-system/confhub/MASTER.md)。

## 视觉与导航

中文管理台采用蓝灰侧栏、中性工作区和绿色主操作，提供浅色及深色主题。字体由应用自身提供 IBM Plex Sans 和 JetBrains Mono，中文使用系统字体。没有虚构的在线客户端数或统计数据；服务状态来自真实 readiness 接口，并显示最近检查时间。

配置管理遵循 Namespace → Group → 配置名称。列表按名称分页，每页 25 项；搜索遍历整个分组的元数据，不读取全部配置正文。详情可深链接，配置名包含扩展名时刷新仍能正常加载。

窄屏导航使用 Radix Dialog 管理焦点、Escape 与返回焦点；标签页支持方向键、Home/End。主题 token 集中在 `frontend/src/styles.css`，响应式覆盖 375/768/1024/1440px，支持减少动态效果，窄屏差异视图纵向排列。

## 编辑与确认

编辑区使用 CodeMirror 6，支持 text、JSON、YAML、TOML、XML、Properties 和 INI 高亮。页面和语言扩展按需加载。只有用户点击格式化才改写 JSON/YAML，格式化进入撤销栈；YAML 多文档及注释保留。输入大小、说明字节数与常见语法先在浏览器检查，最终校验仍由服务端完成。

编辑时不显示 diff。保存后打开只读差异，默认比较当前编辑目标版本：全量目标或选中规则固定的灰度版本。切换比较版本只改变查看对象，保存仍携带原配置 `id` 和 `revision`。用户须勾选内容与影响范围确认后才能发布；相同正文不会生成新版本。

全量保存只更新全量版本；原灰度规则继续固定自己的版本。选择灰度编辑目标后，保存只更新该规则。版本说明可以为空。历史列表提供正文查看、任意两版比较、引用标识和回退；回退复制内容生成递增的新版本，并使用服务端生成的来源说明。

并发冲突保留草稿，阻止直接再次提交，要求读取最新基准并重新比较/确认。配置删除重建导致身份变化，或编辑的灰度规则已删除时，阻止旧草稿覆盖新对象。浏览器内导航和页面关闭均提示未保存内容；历史/规则操作不会清掉未保存的编辑正文。草稿保存在页面内存中，不持久化配置内容或密码到 localStorage。

## 灰度及组织管理

规则从上到下第一条匹配生效，规则内条件为 AND，支持 `eq` 与 `in`。可以新增、编辑条件与固定版本、启用/停用、移动顺序及删除；每次都展示原/新规则及影响范围并确认。灰度内容可以复制为全量新版本。标签试算调用服务端解析器，显示命中版本和规则；输入或配置修订改变后，旧结果失效。

命名空间与分组支持创建和删除。删除需输入名称，仅允许删除空组织。配置删除需输入完整名称，明确说明全部历史及灰度规则会永久删除。管理账户固定为 admin，支持修改密码；错误的当前密码不会误触发重新登录，登录过期以弹窗重新认证并保留草稿。网络失败的退出操作提供重试，不伪报已退出。

## 构建与部署

React 19、TypeScript、Vite、TanStack Query、React Router、Radix Dialog 与 CodeMirror 6 的实际版本由 npm lockfile 固定。构建不依赖 CDN 字体或脚本。

根 Dockerfile 包含 Node 构建阶段、Go 构建阶段和无 Node 的运行镜像。React 构建目录复制到 `/app/frontend`，不嵌入 Go 可执行文件。Compose 任一应用实例均提供完整管理台和同源 API，共享数据库与 JWT 密钥。

本地开发和测试命令见 [README](../README.md)。前端 API adapter 负责路径编码、认证区分、取消请求、分页和友好错误；配置编辑基准独立于 TanStack Query 缓存，避免后台请求覆盖编辑中的正文。
