## 环境与隔离

云端和边缘分别部署一个 Docker Compose 项目，各有独立 PostgreSQL 和两个 ConfHub 实例。两个项目通过专用测试网络连接；NATS 场景额外运行真实 Broker。应用限制为 1 CPU/1 GiB，数据库为 1 CPU/2 GiB，NATS 为 0.5 CPU/256 MiB。

PostgreSQL 镜像为 `registry.cn-hangzhou.aliyuncs.com/bodesi/postgres:17`，NATS 镜像为 `registry.cn-hangzhou.aliyuncs.com/bodesi/nats:2.12.15-alpine-curl`。程序生成随机项目名、端口和凭据，不使用现有部署数据；测试结束清理本次容器、卷和网络。故障注入仅操作这些测试资源。

## 单元与真实依赖集成测试

`make test-full` 创建自己的 PostgreSQL/NATS，执行同步协议和存储测试，并启用 Go race 检测。无需依赖的通信、暂存、参数和心跳测试也包含在 `make test-unit`。

- Protobuf：字节级已知记录、64 位大整数、纳秒时间、中文及控制字符保真；非法长度、截断、旧 JSON、错误协议版本、非法时间戳均拒绝。NATS 使用标准 Protobuf 客户端直接建连并验证 token/版本拒绝；导出用标准解码器验证互操作。
- 协议：主配置、beta、规则增量；分片流控；丢失结束帧、错误序号、错误摘要、错误请求 ID、截断记录均不能修改已提交镜像或游标，随后重连可恢复。
- 存储：一致快照与并发导出、幂等应用、删除重建、移动身份、租约世代隔离、过期日志触发全量、来源变化和游标回退拒绝、私有代次分批写入、导入取消保留旧镜像、导入中途租约接管后旧任务不能激活，以及切换后的有界回收。
- 慢导入：以 3 秒租约执行超过 8 秒的导入，证明暂存写入不阻塞续期；在后续批次注入数据库阻塞，验证旧配置仍可读、清理不会删除有效暂存。
- NATS：4 MiB 全量配合慢接收端，验证有界接收队列与应用层背压；两个独立边缘数据库均收到同一发布；错误 token 拒绝、遗留会话过期；下行增加 100ms 延迟时发送 8 条消息不再逐条等待 Broker Flush。
- 静默断网：TCP 代理保留套接字但丢弃双向数据，验证云端 Broker 连接及时释放，让外层重新连接；不依赖 TCP 主动关闭。
- 共享发布：32 个同步会话共享一个水位轮询任务，数据库读取次数不随会话数增长。
- 全量通知补偿：96 个不同订阅键，每次读取延迟 12ms，超过单次轮询的整体刷新预算仍持续就绪并最终收敛；刷新期间发布的新事件不会跳过。清理旧日志不能使全量重置水位倒退。
- 心跳：源轮询设为 30 秒仍发送独立心跳；源水位从 0 前进到 7，下一次心跳必须发送 7，避免误判来源倒退。
- 边缘控制台：登录保护、错误密码、退出撤销会话、云边 Cookie 相互独立、首次同步前读取 503；镜像目录分页、失败替换保留旧目录、全量替换移除旧目录；仅当前主版本和 beta 可见，旧主版本不可查询；本地灰度试算、客户端列表、同步状态，以及直接请求管理写接口被拒绝。Playwright 使用独立云/边数据库及真实同步链路验证只读编辑器、云端发布自动刷新、灰度和在线客户端，包含浅色桌面、深色手机与 axe 检查。
- 服务与迁移：边缘首次就绪、本地登录及只读控制台、HTTP 管理写请求 403 和存储层拒绝管理写入（镜像导入与清理仍可用）、同步认证隔离、schema 6 → 9 保留原配置与管理员、schema 7 边缘断云升级后仍可读取并在首次增量转换为代次存储、schema 8 JSON 镜像离线升级后可读并接受 Protobuf 增量，重启内容保持；包含 Protobuf 数据时拒绝向下迁移且保留可读镜像；正常启动拒绝隐式迁移。

全量回归还运行已有业务、权限、审计、批量操作、并发、随机序列、实例/数据库故障、Go/Python SDK，以及前端类型检查、单元测试和 Playwright 浏览器测试。同步模块的新增测试没有替代这些回归。

## NATS 生产场景复测（2026-10-28）

实际 Broker 断网恢复在首次三轮完整测试中出现两次 40 秒内未追平。通过 Broker 连接/订阅信息与进程栈确认：网络分区后，Broker 可能暂时保留已失效的云端队列订阅，新的会话请求被分配给旧订阅后没有回复，原实现单次请求耗尽整个连接预算。

修复将会话握手改为总计最多 10 秒、单次请求最多 1 秒的有界重试；每次重试创建独立会话标识，认证和协议拒绝直接失败。新增真实 NATS 回归用例先将请求交给无响应队列成员，原实现失败，修复后连续 10 次通过。未延长原有 Compose 恢复断言的超时。

| --- | --- |

## 空灰度规则的详情页回归（2026-11-09）

实际 edge 的无灰度规则配置返回 HTTP 200，但 `rules: null` 导致前端读取规则数量时报错，显示“页面暂时无法显示”。原因是 Protobuf 的空 repeated 字段解码为 nil slice。解码时初始化空规则列表，使镜像读取稳定输出 `rules: []`；前端详情 API 同时将旧后端返回的 null 规范化为空列表。现有镜像无需重建或修改配置数据。
