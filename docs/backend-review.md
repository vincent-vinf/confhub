# 后端代码审查

审查基线：`9e38920`，首个实现提交：`a07affb`。使用 mattpocock-skills:code-review 的双轴审查，规范与需求由两个独立 agent 只读检查；发现问题后再次检查工作区修复。需求范围为后端、单元测试和必要 PostgreSQL 集成测试；MySQL 保留实现支持，不执行其集成测试；前端、SDK、压测均不在本次实现范围。

## Standards

没有发现额外的明确命名或模块边界规范违规。领域命名符合 GLOSSARY.md，配置事务和同步逻辑集中于具有实质行为的模块。

初审独立发现的问题：

- P1：MySQL 初始迁移给四条 INSERT 追加了仅可用于 CREATE TABLE 的 ENGINE、CHARSET、COLLATE 选项，导致空库初始化失败。
- P2：Session.Next 先取待发送快照再检查 deadline，持续待发送流量可能挤占 WebSocket Ping，最终关闭健康客户端。
- 可选设计建议：CopyVersion 的位置参数加 rollback 布尔值可以改为一个带明确操作类型的请求结构。这是 Data Clumps / Primitive Obsession 的判断性建议，不是规范硬性违规。

修复：INSERT 表选项已移除；Next 在取快照前检查 context，WebSocket 写循环也独立检查心跳时钟。新增待发送状态与已过期 deadline 的回归测试。

复查未发现新的阻断问题或明确规范违规。watchdog 中的 lastSuccess 与就绪状态在同一互斥锁下访问，连接关闭在锁外进行，避免递归锁。可选请求类型建议暂缓，现有接口已说明语义。

## Spec

初审发现的问题：

- P1：MySQL 初始化语法错误违反“两种存储后端正式支持、产品行为一致”的要求。
- P2：故障计时从查询失败返回后开始，并等下一次查询完成才检查，默认黑洞故障可保持就绪约 3 秒；大轮询间隔进一步延迟。这违反连续同步失败 2 秒后退出就绪、关闭连接的要求。

修复：MySQL INSERT 已修正；增加独立 watchdog，按最后成功同步时间撤销就绪，不等待正在阻塞的查询或下一次轮询。轮询间隔限制为失败时限的一半以内。黑洞数据库测试先复现延迟失效，再验证修复。

复查未发现新的可确认阻断问题。检查了 watchdog、消费循环、Session 的锁顺序及恢复交错，没有发现可复现的数据竞争或漏通知路径。恢复清理旧连接及缓存，再从权威状态重建订阅。新增测试还验证了迁移幂等、dirty 拒绝、独立迁移连接池、迟到初始快照、订阅上限、JWT 校验和实际 HTTP 跨实例 WebSocket 推送。未引入前端、SDK 或压测范围扩张。
