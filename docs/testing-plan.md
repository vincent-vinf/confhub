# ConfHub 测试计划

日期：2026-10-10。状态：三个阶段的测试入口、主要场景和覆盖率门槛已落地，并完成完整回归。本文保留测试范围与验收标准；复现命令、实测结果和统计范围见 [测试运行指南](testing.md)。MySQL、容量及性能指标仍不在本次验收范围内。

业务依据：[需求边界](requirements.md)、[关键架构](architecture.md)、[共享 beta 规格](shared-beta-spec.md)、[在线客户端规格](client-presence-spec.md)、[接口](backend-api.md)及 [SDK](sdk.md)。

## 目标与边界

- 覆盖主版本、配置级唯一 beta、灰度规则、回退、删除重建、跨实例传播和 SDK 恢复的完整链路。
- 同时验证正常路径、输入边界、错误路径、事务一致性、并发竞争与故障恢复。
- 提供独立 Go 系统测试程序，通过管理 HTTP API 和正式 Go/Python SDK 测试已运行的系统。
- 数据库集成仅验收 PostgreSQL 17，镜像使用 `registry.cn-hangzhou.aliyuncs.com/bodesi/postgres:17`。MySQL 本阶段不纳入验收。
- 并发测试验证正确性，不开展容量压测，不据此宣称连接规模、RSS 或性能目标已达成。
- 覆盖率用于发现遗漏，不能替代关键场景断言。

## 分层测试

| 层级 | 依赖与接口 | 核心断言 |
| --- | --- | --- |
| 单元测试 | 纯函数、可控时钟或受控依赖、SDK 测试服务 | 业务性质、边界、错误与竞态 |
| 数据库集成 | 真实 PostgreSQL、独立数据库或 schema | 事务、版本、锁、迁移与清理 |

### 单元测试

服务端重点：

- 灰度：规则顺序、条件 AND、`eq/in`、未命中回全量、停用后继续匹配；标签缺失、空字符串、大小写及空白的字面语义。
- IP 区间：端点包含、区间内外、数值排序、IPv4/IPv6、IPv4 映射地址、非法地址、zone、不同地址族及反向区间。
- 输入：配置组织名称、各种格式、空内容、中文、特殊字符、最大字节数及超限；规则、条件、标签和订阅数量限制。
- 同步：初始快照与新事件竞争、旧结果晚到、缓存失效、同键合并加载、事件合并、慢消费者、取消订阅及容量释放。
- 启动参数：flag/env 优先级、默认值、非法值及轮询间隔和同步失败时限约束。

Go/Python SDK 重点：

- GET 原文保真、地址切换、超时、取消、不存在及无缓存时的明确失败。
- 首次订阅、重复订阅、数量限制、取消订阅、关闭、重复关闭及并发生命周期操作。
- beta 编号固定为 0 时，正文或格式变化仍触发更新；无有效变化不重复回调。
- 慢回调、回调异常、旧连接消息、重连期间增加或移除订阅；Python 同步及 asyncio 接口不阻塞事件循环。
- 缓存按集群、配置键及标签上下文隔离；原子写入、重启恢复、删除清理和旧 GET 响应不能覆盖新快照。

Go 使用 `-race`。Python 检查异步任务、线程、连接的关闭与取消。对 IP、标签、格式校验增加 fuzz，以不崩溃、边界正确和语义保持为断言；保存失败样本以便复现。

### PostgreSQL 集成

- 主版本不可变，编号递增；无变化保存不产生版本，描述行为符合业务规定。
- 配置最多一份 beta；首次按指定主历史复制，多条规则共享，修改覆盖且不占主版本号。
- 停用规则保留 beta，删除最后一条规则清除 beta；再次创建需要重新选择来源。
- 全量发布和回退不改变 beta；回退复制为新主版本并说明来源；beta 转全量保留规则和 beta。
- 配置、版本、规则、编辑基准和变更事件在同一事务中生效；取消、校验失败或注入的事务故障不留下部分数据。
- 变更事件符合提交顺序；跨配置并发写入不能使消费者遗漏已提交事件。
- 删除重建使用新身份，旧基准不能覆盖或复活新配置；非空组织不可删除。
- 主历史按配额最终收敛，当前全量受保护；beta 不保护来源主历史，也不受其清理影响。
- 清理租约、分批清理和清理水位正确；清理与保存、回退、首次复制竞争时结果合法。
- 空库初始化和迁移幂等、并发启动安全；dirty 状态及 schema 1/2/3 明确拒绝，不自动 Force 或修改旧数据。
- 在线元数据跨实例共享，租约到期不再返回；标签建议去重、字面前缀、数量上限和特殊字符语义正确。

这一层允许查询数据库验证约束和注入故障。每组测试隔离数据，避免用共享真实业务数据库运行事务或迁移故障用例。

### HTTP 与 WebSocket 集成

- 管理登录、错误密码、JWT 过期/签名/算法、同源校验、操作确认及对应错误码；客户端 GET/订阅无需鉴权。
- 密码修改影响后续登录，重启不覆盖已保存密码；按纯 JWT 语义验证已签发令牌，不假设退出或改密会立即撤销令牌。
- 名称路径编码、输入格式、大小限制、分页游标、非法请求、未知 API 与静态资源路由。
- 客户端返回正文、格式、身份、版本/beta、命中规则和删除状态；管理试算、GET 和订阅结果一致。
- WebSocket 非法操作和消息、重复订阅、订阅上限、取消、Ping/Pong、超时及慢连接关闭。
- A 实例管理修改、B/C 实例读取或订阅，验证广播传播而非竞争消费。

协议错误场景可使用底层 HTTP/WebSocket 客户端；正常获取与订阅链路使用正式 SDK，防止漏测 SDK 行为。

### 前端回归

复用现有 Vitest 和 Playwright：覆盖创建与保存确认、格式化撤销、历史 diff/回退、共享 beta 编辑与转全量、规则顺序和标签/IP 补全、在线客户端、删除重建、重新认证和并发冲突保留草稿。覆盖加载、空态、错误、禁用状态以及明暗主题、键盘焦点和窄屏布局。

不为纯文案或样式调整编写镜像实现的单元测试；业务交互优先通过现有浏览器流程验证。

## 独立 Go 系统测试程序

### 入口与运行模式

独立 Go 入口为 `tests/system`，隔离环境编排脚本为 `tests/run.py`。程序通过公开管理 HTTP API 写入，通过正式 SDK 获取与订阅，不引用服务端 `internal` 包，不读取数据库作为业务结果判据。

| 模式 | 环境 | 执行范围 |
| --- | --- | --- |
| 连接模式 | 使用者提供实例地址和管理员凭据 | 完整业务、跨实例、并发、在线客户端及标签建议 |
| 隔离模式 | 脚本创建 PostgreSQL 和三个应用实例 | 相同场景，加迁移、参数、密码修改、进程与数据库故障 |

支持多个实例地址、场景选择、并发参数、重复轮数、超时、随机种子和报告目录。凭据通过环境变量传入，不写入日志或报告。跨实例套件至少要求两个地址，标准隔离环境使用三个实例；条件不满足时明确失败，不以单实例测试代替。

每次运行创建唯一 namespace 和运行标识，仅删除本次创建的数据。系统级密码、数据库和进程操作只在隔离模式执行。连接模式不改变全局配置、不停止实例。退出及中断时尽力清理；失败记录残留资源标识，清理失败不能静默记作全部通过。

Go 程序负责编排与断言。Python SDK 通过一个小型 asyncio 测试进程参与同一场景，交换订阅就绪、收到的快照和错误等结构化消息；Go/Python 共享场景规格和期望结果。

### 完整业务链路

1. 创建 namespace/group 和配置，验证不同组织下同名配置隔离。
2. Go/Python GET 原文，普通和灰度标签客户端在不同实例建立订阅，确认初始快照。
3. 从另一实例发布新主版本，核对所有应受影响客户端最终结果。
4. 第一条规则从指定旧主版本复制 beta；增加多条规则，验证共享内容和首条命中。
5. 连续修改 beta，验证同名 beta 更新通知、无新增主历史、普通客户端不受影响。
6. 修改条件、重排、停用、重开、删除规则，验证正确回落；删除最后规则后重新复制。
7. 全量发布、主版本回退及 beta 转全量，核对普通/灰度两组客户端、历史和描述。
8. 检查在线连接跨实例可见、订阅已发送状态和标签建议；HTTP GET 不计入在线连接。
9. 删除配置、收到删除通知并清缓存；同名重建后获取新身份及从 1 开始的主版本。
10. 取消订阅、关闭 SDK，验证在线连接最终移除，清理本次数据。

每一步核对正文、格式、版本/beta、规则、身份和存在状态，不只检查 HTTP 200。在线页的 `sent` 仅表示服务端写入成功，不当作客户端已应用确认；SDK 回调结果单独核对。

## 并发矩阵

并发写入用起跑屏障统一开始，同一基准请求使用不同正文，避免无变化保存影响成功数量。固定竞争用例不自动重试；需要冲突后重读再提交时单列场景。测试不依赖随机 sleep 触发竞争。

| 场景 | 断言 |
| --- | --- |
| 同配置、同基准，多客户端全量发布 | 恰好一个成功，其余 409；无覆盖、无额外主版本 |
| 同 beta、同基准，多客户端编辑 | 恰好一个成功；命中客户端最终得到获胜内容 |
| 全量编辑与规则编辑竞争 | 共用编辑基准正确拒绝过期请求，不丢失修改 |
| beta 编辑与最后规则删除竞争 | 符合合法串行结果，不存在孤立 beta |
| 配置删除与旧编辑竞争 | 删除后旧基准不能复活或覆盖配置 |
| 同名配置删除重建与晚到请求竞争 | 新旧身份隔离，旧响应不污染客户端缓存 |
| 多个配置并行写入 | 不串正文、版本、规则或通知；消费者最终无遗漏 |
| 连续发布与大量订阅 | 全部应受影响客户端最终收敛，慢回调不阻塞其他订阅 |
| GET、Subscribe、Unsubscribe、Close 并发 | 无数据竞争和死锁，资源及操作在期限内结束 |
| 历史清理与复制/回退竞争 | 成功结果完整；来源已不存在时明确失败，无部分提交 |

初始建议规模：32 个并发编辑者、100 个订阅客户端、10 个配置，重复 10 轮，均可配置。各竞争场景分别执行；不将这个规模作为容量或性能承诺。

客户端读取允许传播期间短暂旧值。快速连续发布可以合并中间通知，但最终必须收到最新有效配置，旧快照不得覆盖新状态。主版本回退生成新编号；同名重建允许编号重置；beta 始终为 `beta=true/version=0`，因此不能仅用主版本编号判定更新或新旧。

混合并发操作按成功提交及冲突结果检查是否存在合法执行顺序，不强求固定赢家。随机操作序列使用固定种子及独立参考模型验证业务状态，不复用生产路由函数计算期望结果。

## 故障与恢复矩阵

仅隔离模式启用故障注入，不影响运行中的外部系统。

| 故障 | 断言 |
| --- | --- |
| 订阅所在实例退出或重启 | SDK 切换健康地址，恢复全部订阅并取得最新状态 |
| 断线期间多次发布 | 重连初始快照补齐最终内容，不要求重放每次修改 |
| 数据库不可用 | readiness 按失败时限变为不可用，关闭既有会话；SDK 保留最后成功配置并区分离线来源 |
| 数据库恢复 | 状态补偿完成后重新就绪，SDK 恢复正确获取和订阅 |
| 事件日志已清理且节点消费落后 | 触发快照补偿，不能静默跳过而永久停留在旧状态 |
| 初始读取、旧连接或 GET 响应晚到 | 不能覆盖更晚的有效快照或删除状态 |
| 删除后离线及 SDK 重启 | 明确删除已清除缓存，配置不能从磁盘复活 |
| 慢连接、慢回调、心跳缺失 | 有界待发送状态与超时生效，不拖住其他客户端 |
| 实例异常退出 | 在线连接租约到期不再查询到，残留元数据最终清理 |

重启和租约场景区分服务恢复、SDK 恢复、在线列表最终一致性，不统一套用配置通知延迟。实例故障恢复目标从检测断线之后计时，断线检测本身单独记录。

## 验收、覆盖率与报告

统一入口现已启用以下门槛；当前实测数值及覆盖率统计方法见 [测试运行指南](testing.md#覆盖率与报告)：

| 范围 | 覆盖率门槛（Go 按语句，Python 按行） |
| --- | --- |
| 业务规则模块 | ≥90% |
| Go/Python SDK，分别统计 | ≥85% |
| 后端总体 | ≥80% |

统计范围与排除项固定并记录原因，不通过排除业务代码或只挑高覆盖包提高数字。前端同时统计逻辑行/分支覆盖率，以关键交互完整为首要验收条件，待基线建立后确定门槛。

所有必选业务、并发和故障场景必须通过。Go race、静态检查、Python 类型/代码检查、前端类型与构建检查均纳入对应套件。必须执行的数据库、SDK、跨实例测试缺少环境时直接失败；开发者单独执行单元套件允许明确 skip 不适用的集成测试，但报告不得当作集成通过。

使用有期限的条件等待、订阅就绪屏障和受控时钟，减少固定 sleep；预期的“未受影响客户端不回调”使用明确观察窗口。自动重试仅用于等待最终一致结果，不能隐藏断言失败；失败重跑保留首次失败结果。

延迟在独立正常环境记录 P50/P95/P99。发布响应成功至 SDK 收到相应内容可作为黑盒观测指标，但响应可能晚于事务提交，不能代替 [需求](requirements.md) 中“事务提交至 SDK 获得内容”的 P99 ≤300ms 验收。正式性能验收需另外明确提交时刻测量和负载；当前不展开压测。普通正确性回归使用明确超时验证最终收敛。

每次运行生成终端摘要、JSON 和 JUnit 报告，包含：

- 代码版本、运行模式、环境、实例数量、场景、并发参数、轮次和随机种子。
- 通过、失败、跳过及清理结果，场景耗时，延迟观测的口径及样本数。
- 失败操作序列、测试资源标识、脱敏的期望与实际结果、错误码及 SDK 状态。
- 隔离环境的服务日志；前端失败截图/trace；覆盖率报告及 fuzz 失败样本。

不记录凭据或非测试配置正文；报告和日志产物存放到 Git 忽略的目录。失败返回非零退出码，可用于本地脚本和后续 CI。

## 落地顺序

| 阶段 | 交付物 | 验收 |
| --- | --- | --- |
| 1：补测试基础 | 现有用例清单、覆盖率基线、分层入口、业务边界及事务并发用例 | 隔离运行、关键断言、race 和明确缺环境失败 |
