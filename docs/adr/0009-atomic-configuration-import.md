# 配置导入采用整包事务

状态：已接受，2026-11-09。相关规格：[Nacos 配置导入导出](../nacos-import-export-spec.md)。

## 背景

Nacos ZIP 导入逐项提交，ABORT 遇到同名冲突时停止后续操作，先前成功的配置已经生效。采用相同文件格式并不要求复刻这种提交语义。ConfHub 现有批量删除与移动使用整批事务，用户本轮明确选择导入也必须整包提交或整包失败。

## 决定

一次导入的待写配置使用同一个数据库事务。配置、主版本和变更事件统一提交；任何导致导入失败的错误均不能留下本批部分配置修改。若允许随包创建缺失分组，该创建也必须在同一事务中。

支持冲突跳过时，跳过属于策略明确排除的配置，其余待写配置仍作为一个批次原子提交；具体策略及权限边界见已确认规格。批次确认后覆盖配置沿用普通全量发布，保留现有 beta 和规则。

## 后果

不能在导入循环里直接调用各自提交的普通 Save；需要复用其业务校验与保存逻辑，同时共享外层事务。大包会延长事务和配置变更流锁的持有时间，因此实现必须设置批次大小限制并在写事务前完成包解析和预检。

Nacos 的文件交换格式保持兼容，导入失败时的提交行为有意采用 ConfHub 的整包保证；结果展示必须明确已提交或未提交，不能把故障造成的部分写入呈现为成功。
