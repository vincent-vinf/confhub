# 灰度使用可覆盖的临时内容

主版本继续使用不可修改的数字编号快照并提供历史和全量回退；灰度改为从全量内容开始编辑的临时版本，例如 V4-beta，后续编辑直接覆盖当前灰度内容，不保存灰度修改历史，也不提供灰度回退。灰度通过关闭规则停止生效，以减少版本管理和回退的操作复杂度；这调整了 ADR 0002 中全量与灰度共用不可修改版本序列的决定。

每条规则拥有独立临时内容，创建时复制当前全量内容；名称固定为创建来源的主版本号加 beta，后续全量发布与灰度编辑均不改变名称，也不消耗主版本号。保存仍需格式校验、乐观锁与当前内容到编辑内容的 diff 确认，但不提供灰度历史对比选择。关闭保留内容、重新开启继续使用，删除清除内容；灰度转全量按当前主版本序列生成新版本，并保留规则与临时内容。

不兼容旧配置数据，采用新数据库模型重新初始化；应用拒绝将旧 schema 1 直接升级或通过改迁移标记继续使用。客户端协议仍用整数 version 表示主版本号或 beta 的来源号，并通过 rule_id 区分灰度；通知判断增加规则身份、正文与格式，确保同名 beta 更新可见而无关变更不触发通知。
